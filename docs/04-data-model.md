# 4 Database and query design

## 4A Common conventions

- Use three DynamoDB tables named campusfix-{environment}-core, campusfix-{environment}-discovery and campusfix-{environment}-jobs. All use string pk and sk, on-demand billing and encryption. Only Jobs enables TTL on expiresAt; TTL is cleanup, never authorization or scheduling.
- Every business item includes entityType, schemaVersion=1, campusId, id, createdAt, updatedAt and version. Timestamps are ISO 8601 UTC; TTL is epoch seconds. IDs are UUIDs; reject reserved delimiters in identifiers. Store currency as integer minor units with currency=INR, never floating point.
- Core pk always begins C#{campusId}. User identity references use Cognito sub. A separate global identity item U#{sub}/PROFILE stores display name and verified identity metadata; it has no campus content. Campus membership discovery uses sparse GSI1 entries, then strongly reads membership.
- No item may exceed 64 KB at the application layer. Store each reply, event, participant and file separately. Ordinary body limit is 5,000 characters, title 120, reply 2,000 and ordinary note/reason 1,000. Service-review description allows 3,000 and detailed review decision/corrective text 2,000 as defined in OpenAPI. All arrays have explicit limits.
- Public DTOs omit pk/sk, internal grants, private contact details and file object keys. Repositories return domain objects; serializers apply per-field visibility.

## 4B Core entity catalog

- Campus: C#c / CONFIG. name, slug, status, timezone, verifiedDomains, verificationReference, representativeId, authPolicy, businessCalendar, serviceTargets, featureFlags, quotas, retentionPolicy, policyVersion. Default timezone Asia/Kolkata; business hours and holidays must be configured before pilot.
- Directory entity: C#c / GROUP#g, UNIT#u or CATEGORY#k. Group has kind=HOSTEL|DEPARTMENT|BATCH|CLUB and approverIds. Unit has leadId, backupId, escalationId and active. Category has defaultUnitId, sensitiveDefault and allowedPostTypes. All references must belong to c and be active.
- Membership: C#c / MEMBER#user. status=PENDING|ACTIVE|SUSPENDED|REVOKED, groupIds up to 20, scoped roles up to 20, verifiedEmailHash, approvedBy, joinedAt, expiresAt, authVersion. Staff roles include unitId; sensitive-handler is separate. GSI1 reverse lookup USER#user / CAMPUS#c.
- Membership request: C#c#MEMBER#user / REQUEST#id. groupId, reason, state, decidedBy, decisionReason and decidedAt. Add GSI1 C#c#MEMBERSHIP_REQUESTS#state / createdAt#id for approval queues.
- Invitation: C#c / INVITE#tokenHash. invitedEmailHash, role, groupIds, unitId, inviterId, expiresAt, consumedBy, consumedAt. Store expiry in Core and validate it explicitly; scheduled cleanup can remove expired records later.
- Campus onboarding draft: ONBOARD#requestId / META, with applicantSub, collegeName, officialDomain/contact, evidenceIds and state. This global operator-only exception precedes campus creation and contains no existing campus content. Only its authenticated applicant and assigned operator can read it. Evidence reservations bind to that applicant and draft; campus membership is not required to request onboarding.
- Post: C#c#POST#p / META. type=ISSUE|QUESTION|ACTIVITY|LISTING|NOTICE, authorId, title, body, categoryId, locationLabel, audience={kind,groupIds}, aclVersion, publication=DRAFT|PUBLISHED|RESTRICTED|REMOVED, attachmentIds, tags up to 5 and type-specific detail. GSI1 author index; GSI2 issue queue index when applicable.
- Issue detail within Post META: unitId, primaryOwnerId, collaboratorIds, status, severity=LOW|NORMAL|HIGH|URGENT, ackDueAt, updateDueAt, nextAction, nextUpdateAt, waitingReason, resolutionId, duplicateOf, pendingTransfer and supportCount. Sensitive cases use caseHandlerIds and never ordinary group visibility. primaryOwnerId is mandatory at publication, defaulting to the unit's duty lead.
- Question detail within Post META: acceptedReplyId, convertedIssueId and answerState=OPEN|ANSWERED. A verified role badge is computed from the current grant plus the immutable role-at-answer record; official answers also need sourceUrl and reviewedAt.
- Activity detail within Post META: organizerId, startsAt, endsAt, joinDeadline, approximateLocation, capacity, acceptedCount, costMinor, approvalLabel and state=OPEN|FULL|COMPLETED|CANCELLED. Exact location/contact is a separate PRIVATE_DETAILS item in the same partition.
- Listing detail within Post META: listingKind=SALE|FREE|LOST|FOUND, condition, priceMinor, currency, pickupArea, state=AVAILABLE|RESERVED|SOLD|WITHDRAWN|EXPIRED and expiresAt. LOST/FOUND closes using WITHDRAWN plus outcome=RETURNED; do not label recovered property Sold.
- Reply: post partition / REPLY#createdAt#id. authorId, body, parentReplyId optional, scope=PUBLIC|STAFF, editedAt, removedAt and roleAtAnswer. One reply nesting level: a child cannot itself have a child. Revision / REV#replyId#version contains prior body with the same or narrower ACL and retention policy.
- Event: post partition / EVENT#createdAt#id. eventType, actorId, before/after safe fields, reason, commandId and visibility. Never put receipt contents or secret tokens into audit payloads. System events identify the triggering rule and source event.
- Support and subscription: post partition / SUPPORT#user or SUB#user. createdAt and notificationPreference. Unique keys enforce one supporter. A user's My Activity lookup uses GSI1 C#c#USER#user / actionType#createdAt#p on the corresponding support/subscription item.
- Assignment/subtask: post partition / TASK#id. assigneeId, unitId, description, state=OPEN|DONE|CANCELLED, dueAt and completedAt. The primary owner remains accountable; tasks do not create co-owners.
- Resolution: post partition / RESOLUTION#id. symptom, cause, action, outcome, evidenceIds, proposedBy/At, confirmedBy/At and state=PROPOSED|CONFIRMED|INVALIDATED. Keep old attempts when reopened; only the currently confirmed attempt is eligible for knowledge review.
- Knowledge entry: C#c#KNOWLEDGE#id / META. sourcePostId, sourceVersion, sourceAclVersion, resolutionId, categoryId, unitId, symptom, cause, fix, outcome, reviewerId, reviewedAt, reviewDueAt and state=ACTIVE|STALE|REVOKED. Inherits source audience; never copies raw private evidence.
- Attachment: C#c#POST#p / FILE#id. ownerId, parentKind/Id, scope, originalName, generatedObjectKey, objectVersionId, sha256, mime, bytes, state=RESERVED|UPLOADED|SCANNING|CLEAN|REJECTED|DELETED, derivativeKeys, scanEngineVersion, uploadedAt, expiresAt and holdId. Names are display text only, not S3 paths.
- Participation: post partition / PARTICIPANT#user. state=REQUESTED|WAITLISTED|ACCEPTED|REJECTED|LEFT, requestedAt, decidedAt, decidedBy and note. GSI1 C#c#PARTICIPANT#user / startsAt#p supports My Activities.
- Inquiry: C#c#INQUIRY#id / META, then MESSAGE#createdAt#id. listingId, buyerId, sellerId, state=OPEN|CLOSED|BLOCKED and lastMessageAt; messages have authorId/body. Separate INQUIRY_REF entries for each participant under their member partition provide chronological lookup. A conditional uniqueness item C#c#POST#listingId / INQUIRY_BUYER#buyerId points to the open thread and is created with it in one transaction.
- Notification: C#c#MEMBER#user / NOTIFY#createdAt#eventId. sourceId, sourceEventId, templateKey, readAt and channelState. Store no complaint preview; render after reauthorization. Preference item PREFS contains digest, mute and subscription choices.
- Moderation case: C#c#CASE#id / META and DECISION#time#id. targetType/Id, reporterId, reasonCode, description, assignedModeratorId, state, restrictedEvidenceIds and appealReviewerId. Authoritative target remains separately permission-checked. GSI1 indexes assigned moderator and state using scoped case pointers.
- Appeal: case partition / APPEAL#id. appellantId, grounds, state, reviewerId, decision, reason and decidedAt. One active appeal per decision. Reviewer conflict checks run before assignment and decision.
- Administrative audit: C#c#AUDIT#YYYYMM / EVENT#time#id. actorId, operation, targetId, reason and safe field diff. A daily job exports to separately permissioned S3 audit storage. It does not claim that infrastructure administrators cannot tamper.
- Service review: C#c#REVIEW#id / META. issueId, replyId optional, requesterId, reasonCode=NO_RESPONSE|INCOMPLETE_FIX|INAPPROPRIATE_CONDUCT|RETALIATION, description, evidenceIds, reviewerId, state=OPEN|IN_REVIEW|ACTION_REQUIRED|CLOSED|ESCALATED, ackDueAt, decisionDueAt, decisionOutcome=COMPLAINT_UPHELD|RESPONSE_UPHELD|INSUFFICIENT_EVIDENCE, decisionId, decisionReason and correctiveAction. RESPONSE and APPEAL child items retain attributed responses and one independent appeal. Add scoped GSI1 reference items for requester and reviewer queues. Private allegations are not serialized in the issue DTO.
- Activity team: activity post partition / TEAM with leadId, coordinatorIds up to 3, delegatedAdmissionIds and archivedAt; UPDATE#time#id for team posts; TEAMTASK#id with title, assigneeId, dueAt, state=OPEN|DONE|CANCELLED. Only accepted participants can read. Roster visibility is per-member opt-in; organizers still see the operational participant list. Team attachments use the participant ACL, never the public activity audience.
- Review context request: service-review partition / CONTEXT#id. ownerReviewerId, recipientId, sanitized questions/context, attachmentIds, state=DRAFT|SENT|RESPONDED|CLOSED, requestedAt and response. The recipient reads only this DTO and files shared specifically under it; this is not a grant to the parent review. Add a recipient GSI1 pointer for private inbox lookup. The reviewer sends a prepared request after reviewing exactly what will be disclosed.
- Daily metric: C#c#METRIC#YYYYMMDD / UNIT#u#scope. totals, confirmation/reopen/decline/duplicate counts and bounded latency buckets. Only campus-public ordinary issues contribute to student-facing unit metrics; other metrics require equivalent scope authorization.

## 4C Physical indexes

- Core GSI1: gsi1pk and gsi1sk, KEYS_ONLY. It supports one explicitly documented lookup per item; create small reference items where an entity needs more than one lookup. Rehydrate canonical data before returning any result.
- Post author keys: gsi1pk=C#c#AUTHOR#user; gsi1sk=createdAt#postId. Queue keys: gsi2pk=C#c#QUEUE#unitId; gsi2sk=nextActionDueAt#postId. GSI2 is KEYS_ONLY and only includes active issue states. Queue status filters are applied to a bounded candidate page.
- Discovery entries contain only canonical pk/sk, createdAt and sourceVersion. Feed pk=C#c#AUD#CAMPUS|GROUP#g|USER#u#TYPE#type; sk=createdAt#postId. Use an unambiguous encoder for scope segments. Publish one type-specific entry per audience; author and explicit handler feeds use USER entries. Restricted cases never enter CAMPUS/GROUP partitions.
- Resolution lookup pk=C#c#KNOW#categoryId#AUD#scope; sk=reviewedAt#knowledgeId. Activity date lookup pk=C#c#ACTIVITY#AUD#scope; sk=startsAt#postId. Listing active lookup pk=C#c#LISTING#AUD#scope; sk=createdAt#postId. Remove inactive projections as part of transition jobs; canonical checks prevent stale access meanwhile.
- Jobs table: pk=C#c#JOB#eventId; sk=META; kind, sourceId, sourceVersion, state, attempts, runAt, leaseUntil and expiresAt. Ready GSI uses readyPk=READY#shard and readySk=runAt#jobId. Four deterministic shards distribute work; only trusted worker roles query across campuses.
- Jobs also stores idempotency records C#c#IDEMP#user / keyHash with requestHash, resourceId, responseCode and expiresAt; quota counters C#c#QUOTA#user / period#feature; and worker dedup records C#c#DONE / eventId#consumer.
- specs/dynamodb-tables.json is the deployable table shape for local initialization and the reference for CDK. It includes key attributes and GSIs, not every optional domain field.

## 4D Query and pagination algorithms

- Issue detail: strong GetItem on Post META and current membership; check the post's caseHandlerIds where applicable, then Query the post partition with the required prefix for replies/history/files. Never fetch an entire large partition to render one tab.
- Feed: build scope set from campus, active groups and own USER scope. Query the chosen post type by descending timestamp. Merge streams, deduplicate IDs, BatchGet canonical records with consistent reads, authorize and apply filters. Return at most 25 results; inspect at most 200 candidates per request.
- Cursor: authenticated encrypted token containing campus, actor, authVersion, query hash, expiry of 15 minutes and the last CONSUMED key per stream. Do not advance to the last fetched key and discard buffered items. If the 200-candidate bound is reached, an empty page can still return a continuation cursor. Reset cursor when membership or filters change.
- Group membership adds no historic fanout: query the group's partition using current membership. Revocation denies canonical reads even when projections or the browser cache are stale. Never trust a GSI for revocation because GSIs are eventually consistent.
- My Activity: GSI1 by author, support, participation or inquiry reference; rehydrate and check. Staff queue: GSI2 by authorized unit plus direct assignments; strong-read returned posts. Local successful writes update the UI from the response while indexes catch up.
- Library: category plus permitted audience partitions; fetch at most 100 recent reviewed cards, authorize source post and current resolution, then rank. No unbounded table scan or exhaustive-search promise.
- Notifications: Query own member partition with NOTIFY prefix; fetch 25, suppress inaccessible source content, and show a generic removed/unavailable entry when appropriate. Avoid exact unread counts that leak lost access.
- Reminder worker: every five minutes Query each Ready shard with runAt <= now, claim with conditional lease, re-read source and due version, then process. Due jobs are created whenever deadlines change; stale jobs become no-ops.

## 4E Transactions and integrity

- Publish issue: validate active directory references and owner; transact membership version check, post version update, first event, up to 14 feed pointers (four audience groups, author, owner and eight collaborators), idempotency record and outbox job. A pending transfer may add one temporary pointer, giving 15. Restricted cases have at most nine handlers plus the reporter. Deduplicate overlapping users. Keep all commands under 100 operations and 4 MB; reject excessive audience or handler fanout.
- Version checks use condition version=:expected and update version=version+1. Return 409 VERSION_CONFLICT with latest version; the UI preserves unsaved input and lets the user compare before retrying.
- Support: conditional Put SUPPORT#user plus atomic increment of supportCount. Remove support uses conditional Delete plus decrement. Repeated equivalent operations are idempotent, not double counts.
- Accept activity participant: transaction checks activity version, state and acceptedCount < capacity; changes participant from REQUESTED/WAITLISTED to ACCEPTED and increments count. Duplicate acceptance cannot increment twice. Leaving decrements once; waitlist promotion is explicit and uses the same transaction.
- Duplicate issues: link records without moving attachments or rewriting history. A bounded background job unions supporters into the target using their unique IDs; it never adds numeric counts blindly. Preserve original creation time and reporter's permission scope. Cross-audience duplicate links must not reveal a private target.
- Referential integrity is application-enforced: check all referenced campus IDs and existence before a write; prevent disabling a unit with open owned issues until a replacement is accepted. Use soft deletion and explicit cleanup jobs.
- Schema evolution: add optional fields with readers tolerating missing defaults, backfill via checkpointed admin jobs, then enforce the new schema. Never introduce a global table Scan in a request path.
